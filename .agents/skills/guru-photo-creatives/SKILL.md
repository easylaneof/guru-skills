# Фотокреативы

Корень инструмента — папка репозитория на три уровня выше этой папки скилла. Все команды ниже запускаются из корня. Если окружение отсутствует, прочитай [INSTALL.md](../../../INSTALL.md) и выполни установку. Полная поставка обязательна: helpers/, remotion/, examples/. Скилл не содержит отдельную копию программы.

## Первый запуск

Когда пользователь просит готовый пример, онбординг или объяснение «как начать», прочитай [FIRST_RUN.md](../../../FIRST_RUN.md). Там есть демо без ключа, готовые запросы для своего фото и инструкция для пошагового сопровождения. Начни с демо; не требуй Kie.ai для наложения текста. Не запускай все учебные упражнения автоматически: продолжай по запросу пользователя.

## Выбери нужный процесс

- Готовое фото + текст: копируй фото в `remotion/public/assets/`, создай бриф и рендери локально. Не вызывай генератор.
- Новое изображение на основе фото: используй Kie.ai и `--image-input`, затем тот же процесс наложения текста.
- Правка текста или кадрирования: редактируй существующий бриф и перерендери. Не перегенерируй фото.

Из запроса нужны исходник (файл или прямая ссылка), желаемое изменение сцены, точный текст/пресет, количество вариантов и форматы. Уточняй только недостающие решения. Для запроса «все форматы» используй 1x1, 16x9, 9x16. Не придумывай рекламные обещания. Пресеты — в [COPY_PRESETS.md](../../../COPY_PRESETS.md).

## Исходник и генерация

Фото, приложенное к чату, сохрани в `input/`. Если агент не видит приложенный файл на диске, попроси пользователя указать локальный путь. Для URL нужно непосредственно изображение, не страница просмотра облачного диска.

Python: `.venv/bin/python` на macOS/Linux; `.venv\Scripts\python.exe` на Windows.

```bash
.venv/bin/python helpers/generate_assets.py \
  --image-input input/portrait.jpg \
  --prompt "Same person as the reference, preserve facial identity. Holding roses, soft daylight, photorealistic, no text or logos." \
  --name portrait-roses \
  --size 3:4
```

`--image-input` принимает также HTTP(S) URL и JSON-сайдкар от предыдущей генерации. Локальный PNG/JPG/WebP автоматически загружается в Kie.ai. Для сайдкара сначала используется лежащий рядом локальный оригинал; ссылка — запасной вариант. Ссылки провайдера могут истекать. Ошибка ссылки не повод создавать новый исходный портрет: используй сохранённое фото.

Фотографию для img2img всегда передавай через `--image-input`: без него будет новый человек. Пиши промпт сцены на английском, явно сохраняй личность, меняй только запрошенные детали. Текст рекламы добавляется отдельным рендером, не в промпте изображения. Не навязывай серый фон для всех сцен: он нужен только если его запросили или согласовали.

Каждый запуск генератора расходует баланс Kie.ai. Не делай дополнительных вариантов без запроса. При ошибке или таймауте сообщи taskId из лога; не запускай автоматически повторную платную задачу. Для выбора размера используй `--size`, например 1:1, 3:4, 9:16, 16:9. Модель по умолчанию nano-banana-pro.

Результат: `assets/<name>.png` относительно `remotion/public/` и JSON-сайдкар с промптом. Открой изображение перед сборкой: проверь внешность и запрошенную сцену.

## Бриф и наложение текста

Возьми [examples/poster-1x1.json](../../../examples/poster-1x1.json) или соседний пример нужного формата. Сохрани копию в `briefs/<id>.json` и заполни:

- `id`: `<визуал>-<пресет>-<формат>`, например `portrait-roses-minuta-1x1`. Без разделителей пути.
- `template`: `PosterStill`.
- `platform`: `1x1`, `16x9` или `9x16`.
- `format.width/height`: соответственно 1080×1080, 1920×1080, 1080×1920. fps=30, duration_seconds=4 нужны рендереру и не делают PNG видео.
- `assets.after_image`: `assets/portrait-roses.png` (путь внутри `remotion/public/`, не абсолютный путь и не URL).
- `copy`: утверждённые headline, headline_accent, subline, gift_pill, cta_button.
- `brand.badge_text`: согласованный бренд.

Если пользователь дал готовое фото по URL для наложения текста, скачай его в `remotion/public/assets/` с помощью доступного файлового/HTTP-инструмента. Для локального фото достаточно копирования. Это не требует Kie.ai.

Доступные настройки существующего макета:

- `copy.object_fit: "contain"` показывает исходник целиком в верхней части кадра на размытой подложке; подходит для квадратного и вертикального форматов, когда важна фигура.
- `copy.object_fit: "cover"` заполняет кадр с обрезкой. Для 16x9 отправная точка `copy.object_position: "center 28%"`; проверь лицо визуально.
- `copy.text_scale: "0.8"` уменьшает заголовок и подзаголовок; CTA остаётся прежним. Используй, если текст перекрывает важную часть фото.

```bash
.venv/bin/python helpers/render.py briefs/portrait-roses-minuta-1x1.json
```

Фактический путь выводится в конце лога. Скрипт группирует результаты внутри `output/`, неизвестные визуалы попадают в `prochee/`. Повторный рендер того же ID заменяет PNG; для отдельного варианта используй отдельный ID. Для трёх форматов создай три брифа на одном ассете, без трёх платных генераций.

## Проверка результата

Открой каждый PNG. Проверь читаемость кириллицы, наличие всех строк, отсутствие нежелательных переносов, видимость лица и полей по краям. Если достаточно изменить текстовый масштаб/кадрирование, исправь бриф и повтори локальный рендер. Верни превью и фактические пути готовых файлов, укажи какие форматы сделаны и были ли ошибки.

Не загружай результат в рекламный кабинет автоматически. Задача скилла заканчивается готовыми файлами.
